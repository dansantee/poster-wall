# Running it on the Raspberry Pi

Tested on a Raspberry Pi 5 (4 GB) with Raspberry Pi OS Lite 64-bit (Bookworm)
and a portrait-mounted HDMI display. Other models are likely fine; nothing here
is Pi 5 specific except the GPU-composited transitions being smooth.

Install instructions are in [the README](../README.md#installation). This
document is about what `setup.sh` actually does and how to operate the thing
afterwards.

## What `setup.sh` does

Run from the repo root, idempotent, safe to re-run:

```bash
./setup.sh --rotate 90
```

1. **Installs packages** — `chromium-browser` (falls back to `chromium`),
   `python3-venv`, `sway`, `wayland-protocols`, DejaVu and Liberation fonts, and
   `seatd`.
2. **Adds you to `video`, `render` and `input`** so Sway can reach DRM and input
   devices, and enables `seatd`. If any group was added, reboot.
3. **Creates a venv at `<repo>/.venv`** and installs `flask`, `requests`,
   `requests-cache` and `pillow`. (Only the first two are imported by `app.py`;
   the others are historical.)
4. **Writes three user systemd units** to `~/.config/systemd/user/`, enables
   lingering with `loginctl enable-linger` so they start at boot without a
   login, then enables and starts them.
5. **Writes `~/.config/sway/config`** — rotates `HDMI-A-1`, hides the cursor,
   and execs Chromium in kiosk mode at `http://localhost:8088`.
6. **Applies boot tweaks** to `/boot/firmware`, backing up each file first:
   `consoleblank=0` (no blanking), `gpu_mem=256`, `hdmi_force_hotplug=1`, and
   exactly one `fbcon=rotate:N` entry.

`--rotate` accepts `0`, `90`, `180` or `270` and drives both the Sway output
transform (degrees) and the framebuffer console rotation (`degrees / 90`). To
change orientation later, just re-run with a different value.

## The three services

```bash
systemctl --user status poster-proxy.service   # Flask API on :8811
systemctl --user status poster-web.service     # static files on :8088
systemctl --user status poster-kiosk.service   # Sway + Chromium

systemctl --user restart poster-proxy.service poster-web.service poster-kiosk.service
journalctl --user -u poster-kiosk.service -e -f
```

They are **user** units, not system units, so every command needs `--user`.
`sudo systemctl restart poster-kiosk` will report that the unit does not exist.

`poster-web` depends on `poster-proxy`, and `poster-kiosk` wants `poster-web`.
Restarting just the kiosk (what the settings page's button does) reloads the
browser without touching the API.

The units are generated by `setup.sh`, so edit the script rather than the files
if you want a permanent change. `docs/systemd-examples.txt` holds an older
*system*-unit variant with the Plex URL and token baked in as environment
variables — useful as a reference, but not what `setup.sh` installs.

## Day-to-day operation

Everything user-facing is on the settings page:

```
http://<pi-hostname>.local:8088/settings.html
```

It shows **Build Status** (host, short commit, clean/dirty, and the dirty file
list), which is the quickest way to confirm what the Pi is running. Buttons:

| Button | Does |
| --- | --- |
| Save Settings | `PUT /api/config` |
| Restart Kiosk | `POST /api/restart-kiosk` — reloads Chromium so new settings apply |
| Test Proxy | `GET /api/ping` |
| Test Plex | Fetches one item through `/api/movies` and dumps the raw response |
| Preview Idle / Preview Now Playing | Opens the kiosk page in a new tab with `?preview=` set |

## Deploying changes

Both workflows go through
[`scripts/poster-wall-remote.ps1`](../scripts/poster-wall-remote.ps1), run from
Windows. It needs the `Posh-SSH` module and reads the host, user, password and
repo path from `SECRETS.md` at the repo root — copy
[`SECRETS-EXAMPLE.md`](../SECRETS-EXAMPLE.md) and fill it in. `SECRETS.md` is
gitignored and must stay that way.

```powershell
Install-Module Posh-SSH -Scope CurrentUser    # once
```

**Repo deploy** — the normal path. The Pi's git commit ends up describing exactly
what is running.

```powershell
git push origin main
pwsh -NoProfile -File scripts/poster-wall-remote.ps1 -Action deploy
```

That runs `git pull --ff-only` on the Pi and restarts all three services.
Fast-forward only, so a stray local commit on the Pi surfaces as a failure rather
than a silent merge. Afterwards, check the settings page shows the commit you
pushed and that all three units are active.

**Direct deploy** — for fast visual iteration, when you want to see a CSS change
on the actual display before committing.

```powershell
pwsh -NoProfile -File scripts/poster-wall-remote.ps1 -Action direct-deploy
pwsh -NoProfile -File scripts/poster-wall-remote.ps1 -Action direct-deploy -Path web/styles.css
```

With no `-Path` it uploads every modified and untracked file (`git diff
--name-only` plus `git ls-files --others --exclude-standard`), then restarts the
services. Source files go over SFTP as UTF-8 text; anything else (the PNG icons)
is copied byte-for-byte.

The Pi's commit is now *behind* what is actually running, and the settings page
will show `dirty`. Do not use the commit to verify a direct deploy — verify the
behaviour instead. Finish by pushing and doing a repo deploy to realign.

**Other actions**

```powershell
-Action ssh       # simple interactive prompt for one-off remote commands
-Action pull      # git pull --ff-only, no restart
-Action restart   # restart all three services
-Action reboot    # sudo reboot (tolerates the dropped connection)
```

## Troubleshooting

**Black screen, no posters.** Check the kiosk unit and its journal:

```bash
systemctl --user status poster-kiosk.service
journalctl --user -u poster-kiosk.service -e
```

Sway failing to start is usually group membership (`video`/`render`/`input`) or
`seatd` — re-run `setup.sh` and reboot.

**Full-screen error message.** The kiosk loaded but `init()` threw. The message
names the cause; the most common ones map to:

| Message | Cause |
| --- | --- |
| "Configuration service unavailable" | `poster-proxy.service` is not running on 8811 |
| "Plex authentication failed" | Bad or expired `plexToken` |
| "Plex section … not found" | Wrong `sectionId` |
| "Plex configuration incomplete" | `plexUrl` or `plexToken` empty |
| "No movies found in the specified Plex section" | Right section, no movies or shows with artwork |

There is no retry loop, so fix the cause and restart the kiosk.

**Posters rotate but "Now Showing" never appears.** All three of these must hold:
`plexDevices` contains the player's IP *as Plex sees it* (check
`http://<plex>:32400/status/sessions?X-Plex-Token=…` and read `Player address`),
the item's library is in `sectionId`, and the item is a movie or an episode.

**Settings save but nothing changes on the wall.** Expected — press **Restart
Kiosk**. The kiosk only reads config at page load.

**Screen blanks after some minutes.** Verify `consoleblank=0` survived in
`/boot/firmware/cmdline.txt`; `setup.sh` leaves timestamped `.bak` copies beside
it.

**Wrong orientation.** Re-run `./setup.sh --rotate <deg>` and reboot. Sway
transform and `fbcon` rotation both come from that one flag.

**Confirming which code is live.** `GET /api/build-info`, or the Build Status
panel. `dirty: true` means files on the Pi differ from its commit — normally the
signature of a direct deploy.
